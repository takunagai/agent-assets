# drive-public-harvest ─ 公開 Drive フォルダの一括取得

リンク共有された Google Drive フォルダを、認証もブラウザも使わずに列挙・一括取得するスキルの人間向け解説。スキル本体は `skills/drive-public-harvest/`。

## 何を解いているか

Drive の共有フォルダを AI に辿らせると、ふつうは chrome-devtools で 1 画面ずつスナップショットを撮ることになる。これが遅い・高い・不正確の三重苦になる。

2026-09-05 に 61 フォルダの製品素材集（アフィリエイト提携先が配布しているもの）を扱った実測:

| | ブラウザ | curl |
|---|---|---|
| 1 フォルダの列挙 | 5〜8k トークン | 約 200 トークン |
| 取得できる件数 | **50 件で打ち切り** | 全件 |
| 並列 | 不可 | 可 |
| Chrome が落ちたら | 止まる | 無関係 |

決定的なのは 2 行目。Drive のフォルダページは仮想スクロールで、DOM に 50 件しか出ない。**エラーもメッセージも出ない**ので、61 件を 50 件と思い込む。実際にこの罠を踏み、探していたフォルダを「存在しない」と誤判定しかけた。

`https://drive.google.com/embeddedfolderview?id=<ID>#list` は同じ内容を打ち切りなしの素朴な HTML で返す。ここが技術の核。

## 使い方の勘所

3 ステップに分かれている ─ **列挙 → 絞る → 落とす**。真ん中を飛ばさない。

素材集の類は「他機種の写真が同じフォルダに同居」「販促バナー・比較表・文字入りのプレスリリース稿が混在」が普通で、全部落とすと的外れなものが大量に混ざる。`--tree` が返す `path`（フォルダ名を積んだもの）を読んで採否のルールを書き、絞ってから落とす。この `path` は取り込み先の台帳にそのまま残せば、あとから「どのフォルダの何番か」を追える。

落としたあとも、そのままは使わない。ファイル名は `01` `2 (2).png` のように意味を持たないことが多く、重複や機種違いが混ざる。内容ハッシュで重複を潰し、採用候補はコンタクトシート（`data:` URI 埋め込みの HTML）にして Artifact で publish し、目で見て選ばせる。

## 踏んだ罠

- **拡張子なしのファイル名がある。** `01` `02` のような名前で、実体は PNG。名前で画像判定すると全部取りこぼす。同梱スクリプトはマジックバイトで判定している
- **フォルダとファイルの判別はアイコン画像ではできない。** `href` が `/drive/folders/` を指すかで見る
- **100MB 超は確認ページが返る。** `confirm=` トークンを拾い直すか、数が少なければブラウザで落とす
- **公開共有＝自由利用ではない。** プレスキットは「報道目的限定」が多い。取得と掲載可否は別の判断で、後者は人間に渡す

## 壊れたとき

HTML スクレイピングなので、Drive が DOM を変えると列挙が 0 件になる。代替は Drive API v3（公開ファイルなら API キーだけで `files?q='<ID>'+in+parents`）。こちらのほうが堅いが API キーの用意が要る。

列挙が 0 件になる原因は「非公開」「ID 違い」「HTML 変更」の 3 つ。まず共有設定を疑い、非公開ならそこで初めて chrome-devtools に切り替える。
