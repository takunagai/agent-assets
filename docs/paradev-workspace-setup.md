# paradev-workspace-setup

Paradev（旧 Superset）でワークスペースを作るたびに走るセットアップを、リポジトリに合わせて作るスキルです。新しいワークスペース（git worktree）が、依存関係・秘密ファイル・ローカルの状態がそろった状態で立ち上がるようにし、使い捨てのワークスペースで dev を起動して、主要ページがメインと同じ中身で出るところまで確かめます。

---

## 公式スキルとの関係

Paradev のデスクトップアプリは、公式スキル `superset:setup` を配っています。このスキルはその上に足す形で動き、実行のたびに公式スキルと実物の CLI を読みます。

| 公式 `superset:setup` が担う | このスキルが足す |
|---|---|
| 設定の置き場・形式（`config.json` / `config.toml`）・キー・環境変数・形式変換 | 設定画面の判定と「設定には 1 行だけ書く」方針 |
| 使い捨てワークスペースでセットアップが通るかの確認 | dev の起動と、主要ページの中身のメインとの比較、片付けの確認 |
| `.env` をメインから複製するという原則 | 値を読まない複製・権限・上書きしない等の規律、ローカル DB 等の状態の入れ替えコピーと検査、skip 表示 |
| `.superset/` からの移行は「頼まれたら」 | 移行の提案と、調査 → 承認 → 移行 → 確認の手順 |
| ─ | 日本語での案内と、最後の説明（場所・注意点・後から変える方法） |

形式の仕様はこのスキルに書き写していません。Paradev は設定形式の移行中で、書き写すとすぐ古くなるためです。

## できること

- リポジトリを調べて、install のコマンド・複製する秘密ファイル・ローカルの状態・dev とポートを決める（秘密ファイルは名前だけを確かめ、中身は読みません）
- 書く場所（チームで共有するか、このマシンだけか）と、どちらの設定画面かを尋ねる
- `setup.sh` を雛形から作り、設定には `bash ./.paradev/setup.sh`（共有）か `bash "$SUPERSET_ROOT_PATH/.paradev/setup.sh"`（このマシンだけ）の 1 行だけを書く
- 構文チェック（`bash -n`・shellcheck）
- 使い捨てワークスペースを作り、セットアップの完了を待ち、dev を別ポートで起動してメインと比べ、片付ける（作成の前に承認を取ります）
- 設定フォルダが改名前の `.superset/` なら、`.paradev/` への移行を提案する

## 使い方

対象のリポジトリで、Claude Code に話しかけます。

```
Paradev のセットアップスクリプトを作って
ワークスペース作成時に .env と依存関係を自動で準備したい
ライフサイクルスクリプトのセットアップ欄に入れるものを作って
新しいワークスペースで .env が無くて dev が起動しない
```

クラウドのワークスペースは対象外です（公式の `superset:environment` を使います）。

## 流れ

1. 公式スキル `superset:setup` と CLI を読む
2. リポジトリを調べる（変更しない）
3. 設定フォルダが `.superset/` なら、`.paradev/` への移行を提案する（承認されたら移行だけを先に行う）
4. 書く場所・設定画面・複製するものを尋ねる
5. `setup.sh` と設定の 1 行を示し、承認を得て書く
6. 構文チェック
7. 使い捨てワークスペースで dev 起動まで確かめ、片付ける
8. 作ったもの・場所・注意点・後から変える方法を説明する

## なぜ「設定には 1 行だけ」なのか

Paradev 2.0.9 のタブ式の設定画面（「プロジェクトのライフサイクルスクリプト」）は、入力欄の 1 行を 1 コマンドとして保存し、` && ` でつないで実行します。複数行のスクリプトを貼ると、コメント行や `then` の後ろに `&&` が付いて構文が壊れ、何も実行されません。本体を `setup.sh` に置き、欄には呼び出しの 1 行だけを入れると、この問題を避けられます。ほかの落とし穴は `skills/paradev-workspace-setup/references/pitfalls.md` にまとめています。

## 雛形 `setup.sh` の中身

- 実行場所の確認（リポジトリのルートか、メインのチェックアウト自身ではないか、クラウドではないか）
- バージョン管理ツールの PATH の保険
- 秘密ファイルの複製: 値を読まずにファイルごと、`umask 077` と `chmod 600`、既にあれば上書きしない
- ローカル状態の複製: 一時フォルダにコピー → SQLite の整合性検査 → 入れ替え。macOS は APFS のクローンで容量と時間を節約
- 依存関係の install（プロジェクトに合わせて編集）
- 出力の決まり: `copied:` / `skip:` / `setup failed:` / 最後に `setup done`
