# koboyo-icon-jp

日本語の依頼から koboyo の手描き SVG アイコンを探し、**候補を実物のコンタクトシートで見せて選ばせてから**配置するスキルです。koboyo-icons MCP サーバーの薄いラッパーではなく、日本語話者と英語専用検索の間にある摩擦を定型化することを狙っています。Claude Code / Codex の両方で動きます。

---

## 背景 ─ なぜ必要か

koboyo は手描き一筆書きの SVG アイコンライブラリ（71,238 点 / 111 カテゴリ）。人物・場面・マスコットが厚く、Lucide や Heroicons のようなグリッド系アイコンセットとは用途が違います。

MCP サーバー自体はよくできていて、サイズ（縦横比がまちまち・正方形は 4% 未満）と色（単色 `currentColor`）の注意書きを**全ツール応答に毎回注入してきます**。そこはスキルで補う必要がありません。埋めるべき穴は別の 4 つでした。

| 穴 | 実際に何が起きるか |
|---|---|
| 検索が英語のみ | `コーヒー` は 0 件、`coffee` はヒットする。日本語で依頼すると素通しで空振りする |
| 候補が slug の羅列で届く | 手描きアイコンは名前から絵が想像できない。`person-wishlist` と言われて絵が浮かぶ人はいない |
| 7 万点の地図がない | `scene/uistate`（空状態・完了画面用の棚）は、その存在を知らないと翻訳検索では一生辿り着かない |
| 画風の混在 | 手描きなので、別カテゴリから寄せ集めると並べたときに浮く |

3 番目が特に効きます。「空状態のイラストを」と頼まれて `empty state` で全体検索するより、専用の棚を直接見るほうが確実に速く、質も高い。

## できること

| 機能 | 内容 |
|------|------|
| 日本語 → 検索語の変換 | 依頼文を概念の配列にほぐし、英語の一般名詞 1 語に変換。直訳が滑る語（吹き出し / 稟議 / 引き継ぎ）、カタカナの罠（コンセント → `power outlet`、クレーム → `complaint`）、抽象語の比喩化（成長 → `sprout` / `stairs`）を辞書化 |
| 棚（カテゴリ）の当て込み | 111 カテゴリの日本語早見と逆引き表。「空状態」「マスコット」「感情」「抽象概念」など、翻訳検索では届かない棚へ直行させる |
| 候補の可視化 | slug からコンタクトシート HTML を生成。SVG インライン・実寸比保持・ライト / ダーク切替・番号付きカード。**番号で選んでもらう運用**を必須ゲートにしている |
| 画風の統一 | 同じカテゴリ・同じ命名パターン（`confirmation-for-*` 等）から選ばせる |
| 配置の分岐 | コードに埋める（`get_icon_svg`）/ URL 参照 / SVG ファイルとして `~/Downloads/` へ、を用途で振り分け |

## よくある外し方

| やりがち | 何が起きるか | どうする |
|---|---|---|
| 日本語のまま検索させる | 0 件で「該当なし」と返る | スキルが英訳するが、主題語を自分で英語で添えるとさらに確実 |
| 1 個ずつ順番に探させる | 往復が増える | 概念をまとめて渡す。スキルは `find_icons_for` で 1 往復にまとめる |
| 正方形の箱に入れる | 潰れる。正方形は全体の 4% 未満 | 高さか幅の片側だけ指定し、もう片方は `auto` |
| SVG の `fill` を直接書き換える | テーマ追従しなくなる | 祖先要素の `color` を変える（全アイコン `currentColor`） |
| 多語で検索させる | 全語一致がないと近似結果に落ちる | 一番重要な 1 語で引き直す（応答に警告が出る） |
| 画風がバラバラのまま採用 | 手描きなので混在が目立つ | 同カテゴリ・同命名パターンで揃える |
| slug の一覧だけで決める | 名前から絵が想像できず後で後悔する | コンタクトシートで実物を見る（スキルは必須ゲートにしている） |

## 手順（スキルが実行すること）

1. **概念を割り出す** ─ 依頼文をアイコン 1 個に対応する概念の配列にほぐし、各概念を英語 1 語へ。迷う語があれば `references/query-dictionary-ja.md` を読む
2. **棚を当てる** ─ `references/categories-ja.md` の逆引き表からカテゴリを引く
3. **候補を集める** ─ 2 概念以上なら `find_icons_for` に配列で 1 往復（概念ごとに `search_icons` を叩き直さない）。多語クエリの近似フォールバック警告が出たら 1 語で引き直す
4. **コンタクトシートで見せる** ─ `scripts/contact_sheet.py` で HTML を生成し、Artifact で publish するか `open` でローカルビューアに渡す。**承認を得るまで配置しない**
5. **採用分を配置する** ─ 用途で分岐。生成物はスキル配下に置かず、`~/Downloads/` か作業用ディレクトリへ

## コンタクトシート生成スクリプト

```bash
scripts/contact_sheet.py --out <出力先.html> --title "<見出し>" \
  home-outline:ホーム settings:設定 search:検索
```

- `slug:ラベル` のラベルは、その候補がどの概念への提案かを日本語で書く（省略可）
- 標準ライブラリのみ。依存パッケージなし（Codex 環境でも pip 不要）
- 取得に失敗した slug は該当カードにエラー表示され、他の候補は残る
- `--slugs-file <path>` で 1 行 1 エントリのファイルからも読める
- **`--fragment`** を付けると doctype / html / head / body を持たない断片を出力する。Artifact はこれらのタグを自前で付けるため、Artifact に publish するときは必ずこのフラグを使う（付けないとタグが二重になる）。`open` で開く用途ならフラグなし

## 前提

koboyo-icons MCP サーバーの登録が必要です。

```bash
claude mcp add --transport http koboyo-icons https://api.koboyo.com/v1-mcp
```

ライセンスは商用・改変・再配色すべて可、帰属表示不要。ライブラリ自体の再配布と、アイコンの選択・抽出・ダウンロードそのものを機能とするアプリへの同梱は不可。受託納品への埋め込み可否を確認したいときは、スキルから `get_library_info` を呼ばせれば一次情報が返ります。

## 設計上の判断

**サイズ・色・ライセンスの解説を書いていない。** MCP が全ツール応答に SIZING / COLOR を毎回注入してくるため、スキルで再掲すると純粋な二重コストになります。SKILL.md には「応答の SIZING / COLOR 行に従う」の 1 行だけを置いています。

**コンタクトシートを必須ゲートにした。** slug の一覧だけを提示して採用を決めさせない、と明記しています。見えないまま承認を求めるのは往復の空振りになるためです。
