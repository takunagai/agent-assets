# 良いペルソナの条件

AI が作るペルソナは、もっともらしいのに型にはまりやすい（年代や性別のありがちな描写、どの人も似た悩み）。顔ぶれ表の段階と、1 人ずつ書いた後の 2 回、この基準で点検する。

## 1. 顔ぶれの偏りを防ぐ（顔ぶれ表の点検）

- **今のお客さまに寄りすぎない**。決めた比率どおりに「今のお客さまに近い人」と「これから狙いたい新しい層」を混ぜる。今のお客さまの業種や案件をそのまま写さず、同じ困りごとを持つ別の業種・立場・暮らし方に広げる
- **ばらけさせる**: 年代・性別・家族・業種や職業・規模・地域・IT への慣れ。同じ組み合わせ（例: 40 代男性の経営者）を 3 人以上つくらない
- **困りごとの核を重ねない**。同じ困りごとなら、場面・タイミング・きっかけを変える
- **3 条件が全部 ◎ の人ばかりにしない**。△ の人も、比べる材料として 1〜2 人入れてよい（狙わない理由がはっきりする）
- **決めつけない**。「高齢者はスマホが使えない」「女性だから家事担当」のような思い込みで設定しない。そう設定するなら、ナレッジに根拠がある場合だけにする
- **根拠を分ける**。ナレッジのお客さまの話から作った人は「お客さまの声から」、そうでない人は「想像（仮説）」。仮説の人が多いのは問題ではないが、そうと分かるようにする

## 2. 1 人ずつの点検表

- [ ] 仕事・立場に具体的な業種や職種がある（「地域の店舗の店主」ではなく「駅前で 15 年続く美容室の店主」）
- [ ] 数字と固有の場面がある（時刻・回数・金額・場所）。「忙しい」「困っている」だけで終わっていない
- [ ] 「平日の一日」の 1 つに【困りごと】の印があり、「困っている場面」がその時間帯の出来事になっている
- [ ] 代わりの手段が 3 つあり、少なくとも 1 つは同業以外（自分でやる、家族に頼む、我慢する など）
- [ ] 3 つの「不」が別々の困りごとで、「解消すると」が変わった後の姿になっている（サービスの機能を書いていない）
- [ ] 本当に片づけたい用事が、サービス名や作業ではなく、その人の目的になっている
- [ ] 買うきっかけが、困りごとそのものではなく「出来事」になっている（入学、繁忙期の失敗、退職、値上げ など）
- [ ] 買う前のためらいが、3 つの「不」の「不安」と同じ話になっていない
- [ ] 知る・調べる場所が、その人の暮らしや仕事から自然に出てくる（若い人に新聞折り込み、のような不自然さがない）
- [ ] 3 条件の印に、それぞれ理由がある
- [ ] 最初にすすめる商品が `ナレッジ/サービス一覧.md` にある。ないなら「新しく作る案」と書き添える
- [ ] 響く一言が、サービス名ではなく、変わった後の姿になっている
- [ ] 実在の人を特定できない（お客さまの実名・屋号・細かすぎる経歴を使っていない）
- [ ] 文字数の目安（`assets/persona-template.md`）に収まっている

## 3. 名前の付け方

- 年代に合った、ありふれた姓と名にする。実在の有名人と同じ名前は避ける
- 記入例の「佐藤 美穂」と、既にあるペルソナの名前は使わない
- 1 回に作る中で、姓も名の 1 文字目も重ならないようにする（シートの頭文字アイコンが同じ字にならないため）

## 4. よくある失敗と直し方

| 失敗 | 直し方 |
|---|---|
| 全員が同じ悩みで、名前と業種だけが違う | 困りごとの核を先に 1 人ずつ違うものに決めてから書く |
| 属性は細かいのに、困っている場面が浮かばない | 「いつ・どこで・何が起きたか」を 1 つの出来事として書き直す |
| サービスの説明がペルソナに入り込んでいる | 3 つの「不」と用事からサービス名を消し、その人の言葉に直す |
| 都合よく全部 ◎ になっている | 「払ってくれる」の根拠（今すでに何に払っているか）を書けなければ ○ 以下にする |
| 利用者のお客さまの誰かそっくり | 業種・年代・家族構成のうち 2 つ以上を変え、困りごとだけを残す |
