# ゲームフィール ─ 「動くが面白くない」の診断と改良

作品は動くが「感動や面白さがない」と言われたときの進め方。Heartburst（旧称 CatharsisField）Phase 9（2026-09、`docs/improvement-plan.md`・`docs/process-log.md` Phase 9〜9-5）で実証した。

**機能が足りないのではなく、ゲームフィール（操作の手応え）が欠けている**と見て診断すると、改良案が具体的になる。

## 1. 診断の観点

実装コードを読み、次の観点ごとに「今どうなっているか」を 1 行で書き出す。欠けている観点が改良の候補になる。

| 観点 | 欠けているときの症状（Heartburst で見つかった例） |
|---|---|
| 溜めの段階性 | 満充填で頭打ちになり、それ以上溜めても何も起きない |
| 解放前の間（予備動作・無音） | 離した瞬間に爆発し、「来るぞ」という間が無い |
| 音楽との同期 | 爆発がビートと無関係なタイミングで鳴る |
| 結果の変化と蓄積 | 毎回同じ爆発で、何も残らない |
| 触る前の誘い | idle が暗く静かで、触りたくならない |
| 再生環境 | 低音が主役の音作りで、ノート PC・スマホの小型スピーカーでは聞こえない |
| 画面の縁 | 爆発粒子が画面端でワープする。粒子の分布が画面の矩形に沿っていて四辺が見える |
| 光 | グローが無く、爆発が平板に見える |

## 2. 案の出し方と決め方

1. 原因を上の観点で分解する（Heartburst では 8 項目）
2. 改良の軸（Heartburst では爽快感・ゲーム性・楽器・物語の 4 軸）× 工数（S / M / L）で案を並べる
3. AskUserQuestion で、採用する軸・描画基盤（例: p5 2D 継続か）・対象（ウェブのみか）・デバイス（PC とスマホ）を確定する。美的判断はユーザー
4. **作品の核の瞬間（Heartburst では「解放」）の手応えを最初のフェーズにする**。他の軸はすべてその手応えの上に乗るため

## 3. 核の瞬間を強くする技法（解放の例）

- **状態を分ける**: `charging → releasing → decay` を `charging → inhale（吸い込み）→ impact（着弾）→ decay` にする。離してから着弾までの間が「来るぞ」を作る
- **同期の主導権を音側に置く**: 着弾時刻は音響エンジンが決めて返す（`release()` が `ReleaseTiming` を返す契約）。ビジュアルはその時刻まで吸い込みで待つ。音を絵に合わせるより、絵を音に合わせる方が崩れない
- **拍に揃える**: 着弾を次の 16 分音符へ量子化する。弱い解放は量子化しない（待たせない）
- **無音の間**: 着弾直前に全体をダッキングして一瞬静かにする。Strudel 層にも効かせるには出力を奪う（`pitfalls.md`）
- **ヒットストップ + スローモーション**: 物理に `timeScale` を掛ける。摩擦は `FRICTION ** timeScale`（`Math.pow`）で時間の伸縮に合わせる
- **着弾音を帯域ごとに重ねる**: click（高域の輪郭）/ body / exciter（非対称の歪みで偶数倍音を足し、小型スピーカーで低音を「聞かせる」）/ sub。低音だけに頼らない
- **余韻の区間**: 1〜2 小節のドロップ（キック + 裏拍ベース + パターン層のポンピング）
- **視覚**: 速度ストリーク、多層の衝撃波と波面による押し出し、色温度（白熱 → 全色相 → 復帰）、ばねズーム、グロー（別レイヤー。`pitfalls.md`）

## 4. 他の軸の実例（Heartburst）

- **ゲーム性**: 段階チャージ（33 / 66 / 100% で輪・和音・揺れが強くなる）、オーバーチャージ（満充填後も保持すると赤熱・稲妻 → 満了で暴発）、クリティカル（心拍の位相 ±0.12 で離すと金の爆発 + 鐘）、スリングショット（直前 70ms の弾き速度で指向性）、二次爆発の連鎖、idle のホバー反応、スマホの振って解放と振動
- **楽器**: タップ位置が音程になる（x = ペンタトニックの度数、y = オクターブ）。タップした場所に「種」が残り、1 小節 16 分割のループシーケンサーで鳴り続ける。強い解放ごとにコードが進み、音と色が追従する。光の点滅は「聞こえている位置」（出力レイテンシを引いた拍位置）に合わせる
- **物語**: 強い解放のたびに痕跡（光の染み・輪・星屑）を別キャンバスに積み、自分の爆発の履歴が 1 枚の絵になる。N 回目（Heartburst は 7 回目）で大団円の爆発と場面転換（夜 → 夜明け → …）、残り回数を画面下の点で示す。「言葉を書いて、壊す」（入力した文字を粒子で形作り、解放で砕く。入力はブラウザ内のみ）
- **声**: マイクの声量で溜める（任意機能。https / localhost のみ。`pitfalls.md` のマイク・iOS の項）

## 5. 見た目の評価ループで直したもの

演出を足したら、状態ごとにスクショを撮って判断する（`verification.md` 10 節）。Heartburst で見つかった型:

1. **強い状態で画面が空になる**: オーバーチャージ中に全粒子が核に潰れて画面が空 → 稲妻・火花・赤熱の核を足して、潰れている間も画面を埋める
2. **威力を速度に掛けると粒子が画面外へ抜ける**: 1 秒後に空洞になる → 速度の上乗せは抑え（Heartburst は 0.35 倍）、派手さは二次爆発・色・輪で出す
3. **長い余韻が空虚**: 減速した粒子が暗く小さくなり、最大 4.8 秒のドロップ区間が寂しい → 明るさを energy に連動、キックで粒子が脈打つ、きらめき
4. **idle が暗すぎて第一印象が弱い**: 輝度・alpha を上げ、背景の星雲を足す
5. **画面の矩形が見える**: 粒子の配置・回り込み・再流入が画面の矩形基準だと、溜めで四辺が縮み、直線の縁が見える → 画面の外まで伸びる真円（半径 = 対角線の半分 × 1.4）に住まわせ、中心ほど濃く配置する（半径 = R × 乱数^0.7）。円外へ出たら反対側の円周の内側へ戻し、爆発後は円周から内向きに再流入させる（円周は画面外なので出入りが見えない）。画面外の粒子は描画を省く
6. **暗い暖色が濁る**: 星雲の橙〜黄緑が泥色になる → `pitfalls.md` の色相の項
7. **狭い画面で UI が重なる**: 390px 幅で進行の点とボタンが重なる → 狭い画面では配置を変える
8. **連打で素材が枯渇する**（スモークテスト作品 Prism Pop、2026-09-24）: 泡を割る連打型で、12 個割っただけで 25 → 3 個になり空振りが出た。補充が一定間隔（80〜220ms に 1 個）で、しかも画面外から湧いて見える位置まで 1〜2 秒かかっていた → 補充間隔を不足率に比例して詰め（最短 35ms）、不足が大きいとき（30% 超）は画面内に小さく湧かせて膨らませる。連打のペース（150ms 間隔 30 連打）で素材の数と空振り 0 を数値で確かめる
