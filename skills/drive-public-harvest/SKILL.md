# 公開 Drive フォルダの一括取得

## なぜブラウザを使わないか

chrome-devtools で Drive を辿るのは**遅く・高く・不正確**。実測（2026-09-05・61 フォルダの素材集）:

| | ブラウザ（chrome-devtools） | curl |
|---|---|---|
| 1 フォルダの列挙 | snapshot 1 回で 5〜8k トークン | 約 200 トークン |
| 件数 | フォルダページは **50 件で黙って切れる**（仮想スクロール） | 全件 |
| 並列 | 不可 | 可 |
| Chrome が落ちたら | 止まる | 無関係 |

**50 件の打ち切りが一番危ない。** エラーもメッセージも出ないので、「61 件のうち 50 件」を全部だと思い込む。実際にこれを踏んで「目的のフォルダは存在しない」と誤結論しかけた。

## 手順

### 1. フォルダ ID を取る

共有 URL の `/folders/` の直後。`https://drive.google.com/drive/folders/<FOLDER_ID>?usp=sharing` の `<FOLDER_ID>`。

### 2. 中身を列挙する

```bash
S=~/.claude/skills/drive-public-harvest/scripts
python3 $S/drive_ls.py <FOLDER_ID>            # 直下だけ
python3 $S/drive_ls.py <FOLDER_ID> --tree     # 再帰的にファイルを全部
```

`--tree` は `[{id, path}]` を返す。`path` はフォルダ名を `/` で積んだもので、**どのフォルダの何番かを最後まで持ち回れる**（取り込み先の台帳に残すとあとで追える）。

**列挙した時点で構造を読む。** 素材集の類は「他機種が同居している」「販促バナーと製品写真が混在」が普通で、全部落とすと的外れなものが大量に混ざる。`path` を見て採否のルールを書き、絞ってから落とす。

### 3. 絞る

`--tree` の出力を jq / python で絞って別の JSON にする。ルールは「採る条件」と「除く条件」を明示的に書く。

```bash
python3 $S/drive_ls.py <FOLDER_ID> --tree > /tmp/all.json
jq '[.[] | select(.path | test("製品イメージ")) | select(.path | test("Amazon|プレスリリース") | not)]' \
  /tmp/all.json > /tmp/pick.json
```

### 4. 落とす

```bash
python3 $S/drive_fetch.py /tmp/pick.json <出力先> [--workers 6]
```

原本がそのまま落ちる（数 MB 〜 数十 MB。1 枚 8000px 級もある）。`_report.json` に `path` / `id` / `bytes` が残る。失敗分は標準エラーに理由付きで出る。

### 5. 中身を見てから使う

**落としただけで使わない。** ファイル名は `01` `2 (2).png` のように意味を持たないことが多く、機種違い・重複・的外れが混ざる。

- 内容ハッシュで重複を潰す ─ `find <dir> -type f -exec shasum {} \; | awk '{print $1}' | sort | uniq -d`（配布元が同じ画像を別名で 2 回置いていることがある。実例あり）
- **自分でも中身を見る。** 枚数が多いときは ImageMagick でモンタージュにすれば 1 回の Read で一覧できる（下記）。
  文字入りの販促画像・別機種・パッケージ写真はここで落とす
- そのうえで、採用候補はコンタクトシート（`data:` URI 埋め込みの HTML）にして Artifact で publish し、人間に選ばせる。
  ファイルパスの羅列やツールのインライン表示では相手に見えない

モンタージュの作り方（Python 経由。**シェルで組まない** ─ 理由は下の罠の表）:

```python
import pathlib, subprocess
files = sorted(f for f in pathlib.Path("dl/<slug>").iterdir() if f.name != "_report.json")
thumbs = []
for n, f in enumerate(files, 1):
    t = pathlib.Path(f"flat/{n:02d}.jpg")
    subprocess.run(["magick", f"{f}[0]", "-resize", "320x320", "-background", "white",
                    "-gravity", "center", "-extent", "320x320", str(t)], check=False)
    thumbs.append(str(t))
subprocess.run(["magick", "montage", *thumbs, "-tile", "5x", "-geometry", "+6+6",
                "-background", "#d0d0d0", "montage.jpg"], check=False)
```

`-label` はフォントが無い環境で失敗してラベルが出ない。**番号は付かない前提で、並び順（ファイル名昇順・左上から行方向）で位置と対応づける**。

## 詰まったとき

| 症状 | 原因と対処 |
|---|---|
| 列挙が 0 件 | 共有設定が「リンクを知っている全員」でない（ログインへリダイレクト）。**ここで初めてブラウザに切り替える**。ID 違いと Drive の HTML 変更も疑う |
| ちょうど 50 件で止まる | `embeddedfolderview` でなく通常のフォルダページを見ている。スクリプトを使う |
| 画像なのに拾えない | **拡張子なしのファイル名**（`01` `02`）がある。名前で判定せずマジックバイトで見る（スクリプトはそうしている） |
| `想定外の型 text/html` | 100MB 超のファイルは確認ページ（`confirm=` トークン）を返す。返った HTML から `confirm` の値を拾って `&confirm=<値>` を付け直す。数が少なければブラウザで落とすほうが早い |
| フォルダとファイルの判別が狂う | 判別は `href` が `/drive/folders/` を指すかで行う。**アイコン画像では判別できない** |
| スクリプト自体が壊れた | Drive の HTML 構造が変わった。代替は Drive API v3 ─ 公開ファイルなら API キーだけで `https://www.googleapis.com/drive/v3/files?q='<FOLDER_ID>'+in+parents&key=<API_KEY>`。こちらのほうが堅いが API キーの用意が要る |
| モンタージュのタイル数が枚数と合わない | **アニメーション GIF がコマ数ぶん展開されている**。`magick "<file>[0]"` で 1 コマ目だけ指定する |
| `magick "$f[0]"` が空文字になる | **zsh は `"$f[0]"` を配列添字として解釈する**（`$f` の 0 番目 = 空）。`"${f}[0]"` にするか、Python から subprocess で渡す。実例: 2026-09-05 にこれで montage が 0 枚になった |
| フォルダ名は合っているのに目的の機種が無い | 配布元がセット品・シリーズ単位でフォルダを切っていることがある。実例: 「ロックUltra 顔認証セット」には**ロック本体が主役の写真が 1 枚も無かった**（中身は顔認証パッドの訴求画像）。フォルダ名を根拠にせず、中身を見てから機種を確定する。無ければ**素直に見送る** |

## 取得したあと

- **配布元の利用条件を確認してから使う。** 公開共有＝自由利用ではない。プレスキットは「報道目的限定」が多く、商用サイトへの掲載は別途許諾が要ることがある。条件の明文が見当たらないときは、その事実と掲載の根拠を記録に残し、人間に判断を渡す
- 出所（フォルダ URL・`path`・取得日）を成果物側の台帳に必ず残す。あとで「どこから来た画像か」を追えないと差し替えも取り下げもできない

## 使わない場面

- 共有設定が限定されているフォルダ（ログインが要る）→ chrome-devtools
- 自分のマイドライブの操作、アップロード、権限変更 → Drive の UI か API
- Drive 以外の共有ストレージ（Dropbox・Box・ギガファイル便）→ このスキルの手順は効かない
