# 落とし穴（根拠と確認日つき）

Paradev のローカルワークスペース用セットアップを作って動かしたときに分かったこと。版が変わると当てはまらなくなるものがあるので、確認日と版を添える。

## 1. タブ式の設定画面は、欄を 1 行 = 1 コマンドで保存し、` && ` でつないで実行する

- 内容: 「プロジェクトのライフサイクルスクリプト」のセットアップ欄に複数行のスクリプトを貼ると、1 行ずつ配列の要素として保存され、実行時に ` && ` で連結される。コメント行や `do`・`then` の後ろに `&&` が付いて構文が壊れ、何も実行されない
- 根拠: 保存された `config.json` の `setup` が 22 要素の配列になっていた（実測）。画面のコードは改行で分割して配列にする。連結はアプリ本体のコードで確認
- 対策: 本体を `setup.sh` に置き、欄には `bash "$SUPERSET_ROOT_PATH/.paradev/setup.sh"` のような 1 行だけを入れる。`bash` で別プロセスにすると、`set -euo pipefail` がセットアップ用端末のシェル自体に効く心配もない
- 適用範囲: 2.0.9（2026-11-15 の正式版）のタブ式画面で確認（2026-11-18）。ファイル全体を編集する「Workspace config」画面が出る環境では当てはまらない

## 2. gitignore 済みのものは新しい worktree に無い

- 内容: 秘密ファイル（`.env` 系・`.dev.vars` 系など）、ローカル DB・ストレージの状態（例: Wrangler の `.wrangler/state`、SQLite ファイル）、gitignore 済みの設定フォルダそのもの
- 対策: メインのチェックアウト（`$SUPERSET_ROOT_PATH`）から複製する。`setup.sh` が gitignore 済みならメインにしか無いので、`$SUPERSET_ROOT_PATH` 経由で呼ぶ
- 確認: 2026-11-18

## 3. 秘密ファイルは値を読まずにファイルごと複製する

- 内容: `(umask 077 && cp "$ROOT/$file" "$file")` の後に `chmod 600`。`cp -p` は元の権限・ACL を写すので使わない。既にあれば上書きしない。リンク切れの symlink を「無い」と誤判定しないよう `[ -e ] || [ -L ]` で判定する
- エージェント自身も中身を表示・grep しない。存在と名前だけを確かめる
- 確認: 2026-11-18（雛形の動作確認で権限 600 と上書きしないことを実測）

## 4. 状態のコピーは一時フォルダ経由で入れ替える

- 内容: 直接コピーして途中で止まると作りかけが残り、次回は「既にある」として飛ばされ、壊れたまま通る
- 対策: `<dest>.copying` にコピー → 検査 → `mv`。開始時に前回の作りかけを消す（消すのはこのスクリプトが作る一時フォルダだけ）
- 確認: 2026-11-18（壊れた SQLite で止まり作りかけが残る → 直して再実行すると消えて入れ替わることを実測）

## 5. dev 稼働中のコピーは食い違うことがある

- 内容: WAL 形式の SQLite は db・wal・shm を別時点で写すと食い違う余地がある
- 対策: コピー後に `sqlite3 <db> 'PRAGMA integrity_check;'` が `ok` でなければ失敗させる。検出は保証ではない。確実なのはメインの dev を止めてから作ること
- 実地: 2026-11-18 は dev 稼働中に作成しても検査を通った（その間の書き込みは無かった）

## 6. macOS では `cp -c` でクローンできる

- 内容: APFS のクローンで容量と時間を節約できる。clonefile が使えなければ cp 自身が通常のコピーに切り替える（macOS の `man cp`）
- Linux には `-c` が無い。GNU coreutils なら `--reflink=auto`。OS で分岐する
- 確認: 2026-11-18

## 7. 作業フォルダと PATH の保険

- 先頭でロックファイル等の存在を確かめ、ルートでなければ止める
- メインのチェックアウト自身で走ったら何もしない
- バージョン管理ツール（mise 等）が端末の PATH に無いときに補う
- 確認: 2026-11-18

## 8. コピーを飛ばしたら理由を表示する

- 内容: `skip: …` を出す。無言だと、セットアップ前に dev を起動して空の状態ができた場合などに気付けない
- 確認: 2026-11-18

## 9. dev がすぐ戻るフレームワークがある

- 例: Astro 7 の `astro dev` はバックグラウンド化して即終了し、`astro dev stop` で止める
- 対策: 確認で dev を起動するときは、終了コードではなくポートの LISTEN と HTTP 応答で起動を判定する。止めるときはフレームワークの停止コマンドを使う
- 確認: 2026-11-18

## 10. ポート

- Paradev はまだポートごとの変数を渡さない（公式 `superset:setup` の記述。`SUPERSET_PORT_<NAME>` に頼らない）
- 多くの dev サーバーは使用中なら次の番号へずらすが、確認では明示的に別ポートを指定すると比較が楽
- 確認: 2026-11-18

## 11. `mise trust` を無条件に入れない

- 内容: `[tools]` に版だけを書いた `mise.toml` なら trust は要らない（`mise trust --help` に記載）。無条件に trust すると、将来 `[env]` や hooks を足したブランチも信頼してしまう
- 確認: 2026-11-18

## 12. `SUPERSET_ENV` はアプリの端末では `production`

- 内容: 公式 `superset:setup` は、各ステップに `SUPERSET_ENV`（`local` か `cloud`）が渡ると書く。一方、2.0.9 のアプリ内の端末では `SUPERSET_ENV=production` が入っていた。「`local` 以外なら止める」と書くとローカルでも止まる
- 対策: クラウドかどうかは `cloud` との一致だけで判定する
- 確認: 2026-11-18（2.0.9 のアプリ内の端末で、候補値との一致だけを実測。セットアップ用端末で同じかは未確認）

## 13. `config.toml` と `config.json` が両方あると `config.json` は無視される

- 内容: Paradev は `config.toml` を先に読み、両方あると `config.json` を無視する（公式 `superset:setup`）。タブ式画面の中身は `config.json` なので、`config.toml` を足すと画面の設定が効かなくなる
- 対策: 既存の形式を保つ。変換は公式の手順として別の変更で行う
- 確認: 2026-11-18

## 14. 「Workspace config」画面はファイルではなく機能フラグで切り替わる

- 内容: 2.0.9 のコードでは、機能フラグ `workspace-config-toml` が有効ならファイル全体を編集する「Workspace config」画面、無効ならタブ式画面を出す。`config.toml` の有無では決まらない。フラグはサーバー側で決まり、コードからは分からない
- 対策: どちらの画面かはユーザーに尋ねる
- 確認: 2026-11-18（公式リポジトリの `ProjectSettings.tsx`）

## 15. チームで共有する設定は、ワークスペースのブランチから読まれる

- 内容: 新しいワークスペースは自分のブランチの設定を読む（公式 `superset:setup`）。未コミットの `setup.sh` は確認用のワークスペースに入らない
- 対策: チームで共有なら、確認の前にブランチへコミットし、そのブランチを起点にする。設定の 1 行は相対パス（`bash ./.paradev/setup.sh`）にすると、ブランチごとの版が走る
- 確認: 2026-11-18

## 16. macOS の `/bin/bash` 3.2 は `set -u` で空の配列を展開するとエラーになる

- 内容: `"${array[@]}"` が空だと `unbound variable` で止まる（bash 4.4 で解消）。設定の 1 行の `bash` は、PATH によっては `/bin/bash` 3.2 になる
- 対策: `${array[@]+"${array[@]}"}` で展開する
- 確認: 2026-11-18（3.2.57 で雛形を実行）

## 17. 設定にキーが無いときの自動実行に頼らない

- 内容: `config.json` 形式では、`setup` 等のキーが無いと設定フォルダの `<key>.sh` を worktree → メインの順に探して実行する（公開ドキュメント）。`config.toml` 形式では、この自動実行は無くなり `run` に書き出す（公式 `superset:setup` の対応表）
- 対策: 自動実行に頼らず、設定に 1 行を明示する。形式を変えても挙動が変わらない
- 確認: 2026-11-18
